# 模块及验收约定

## 阅读与位置

`ReaderAdapter` 管理一个 foliate-view 生命周期、串行导航、加载监听、原文选区、高亮和学习展示。`LocationAdapter` 对 CFI 生成和解析使用相同的节点过滤；解释节点有 `data-reader-ui` 标志。上游依赖不被修改。元素选区先转成文字边界，避免整个段落的 Element offset 被误认为文本 offset。

Locator 保存文件哈希、章节、CFI、原文引用和前后各 40 字符。引用/上下文不匹配时拒绝跳转，不按相似文字猜测位置。进度捕获原文中的折叠 Range，布局重排期间无效的临时位置不覆盖上次有效位置。

## 内容与搜索

`ContentService` 从未插入解释的章节文档提取段落，不读取界面 DOM。嵌套目录的无链接分组使用第一个可导航子项作为目标。章节按需读取并缓存文本，不为 AI 切换页面。段落上下文使用一次原文遍历得到的字符偏移，避免逐段复制整章前后文；保留原有 CFI 生成与原文校验。DOM 遍历和段落定位按约 1–6 ms 空闲时间片调度，关闭书籍时取消未完成提取。

`SearchService` 管理独立 Worker 的请求及生命周期。传给 Worker 的是纯文本与可序列化位置。`PassageIndex` 使用 Intl.Segmenter 分词，MiniSearch 查询；分词策略在建立索引和查询时相同。书籍更换后关闭旧 Worker，不接受旧搜索结果。首次建索引在阅读页面稳定约 600 ms 后启动，以 40 段为一批传输，主动搜索会提前唤醒并等待索引完整。完整 MiniSearch 快照在 Worker 内写入 IndexedDB，恢复时不重新提取整本书，也不在主线程读写大索引。

共享接口：getOutline、searchBook、readPassage、readSection。读取片段最多扩展前后各三段；章节接口使用字符游标，可继续读取超长段落。navigateTo 仅由读者操作触发。

## 记录与备份

Dexie v3 保留 books、progress、annotations、learning，以及 v2 增加的 agentSessions、agentMessages 保存按书和账号隔离的对话、模型/effort 与引用快照。个人记录独立于可重建检索索引。原文件哈希相同才关联；原始 EPUB 不改写。v3 新增可重建的 searchIndexes 和 cacheState，不改写原有记录。索引按书籍 SHA-256、章节数及索引格式版本校验；清除缓存用事务更换 epoch，阻止清理前启动的后台任务重新写入。原有 version 1 备份格式不变，不包含 AI 对话或检索索引。

备份格式标识 incremental-reader、version 1。先完整校验，再在同一事务合并三张个人数据表。相同位置保留较新记录，重复导入幂等，ID 跨位置冲突时整个事务回滚。无书籍本体时也保留记录，等待以后导入原始 EPUB。备份不包含会话模型设置。

## 模型与工具

`modelClient` 使用一次性 JSON Chat Completions 请求，拒绝带凭据/查询参数的 URL，禁止重定向，密钥只在内存。错误提示不显示提供商响应正文。解释结果完整返回且请求未取消后才保存。

`BookToolSession` 与读者共用 SearchService / ContentService。工具结果中的书籍文本作为不可信资料提供；工具没有导航、写记录或任意执行入口。所有返回给模型的搜索摘录和原文片段均计入 30,000 字符预算，最多执行八次工具调用。

只有实际 readPassage/readSection 返回的片段会生成 R 编号；最终回答中的未知编号被替换为未验证引用。引用卡片显示工具实际读取的原文，不把模型自己生成的引文当作来源。

## 已选择的取舍

- API 采用非流式模型响应；Codex 在侧栏流式显示草稿。解释均在完整返回后保存，正文只绘制已有记录的覆盖标记。
- 选区快捷浮框按 iframe 可见选区定位；翻页、滚动或重排时关闭，笔记和释义分别留在所属侧栏。
- 索引在 Worker 内使用并以完整快照持久化；读写缓存失败时仍可建立内存索引，损坏或旧版本缓存自动回退重建；个人数据与可重建缓存分表保存。
- 当前使用页面和本机服务；翻译转发及 Codex 连接依赖本机服务，不支持只部署静态文件后使用这些功能。无云同步或离线安装。

## 本机 Codex（2026-11-06 实施）

`agent-proxy.ts` 在开发和预览服务中注册同源 WebSocket；一次性凭证放在握手协议头中，校验精确 Host/Origin。`CodexService` 通过 `CodexRpc` 使用 stdio 连接 Codex，检测官方订阅登录并分页读取模型。网页保留书籍和四个只读工具，双向传递工具请求；模型连接、会话、预算和引用校验分层，后续按需增加其他 Agent 适配器。现有 API 连接保留，失败时不自动切换计费路径。

详细边界、会话存储升级、取消与隔离、参考项目和验收顺序见 [本地 Agent 接入设计](local-agent-design.md)。真实订阅与专项测试结果见开发记录。

订阅接入需动态读取模型列表及各模型支持的 effort，提供联动选择并逐轮传递、保存配置快照。阅读场景固定为受限的 Chat 对话策略，可查原文，不能执行电脑任务；Chat 是阅读器产品模式，不能假设 Codex 协议存在同名开关。

Chat 使用独立的本地模型能力副本移除 shell/apply_patch/代码执行等原生工具，配合进程级功能开关禁用插件、MCP、hooks、浏览器、电脑操作、记忆和多 Agent；核对有效配置层、专用只读权限及服务端回调白名单。原始 Codex 模型缓存、全局配置和登录令牌不改写。Windows 的 elevated helper 要求自身具有根目录读取权限，因此不宣称仅靠文件系统只读就能实现隔离；模型文件入口通过移除工具关闭。按实际验证版本启用，未知版本不降级放行。

每轮在浏览器新建 `BookToolSession` 并计入选区原文；引用编号按对话递增，原文读取后先保留编号再回传，取消后不复用。最终核验复用 `verifiedAnswer`。临时解释不注册书籍工具，不写入书籍对话历史。取消在途 turn/start 和生成轮次都需确认停止或关闭本服务创建的进程，不能后台重放。
