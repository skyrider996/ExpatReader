# 全文检索启动优化（2026-11-07）

阅读页卡顿的主要来源是主线程段落提取：原实现对每段调用 `LocationAdapter.capture`，分别复制从章节开头到该段、以及该段到章节结尾的 DOM，再取 40 字符前后文。长章节会反复处理相同内容；仅把分词放进 Worker 无法消除这部分阻塞。

本次改动：

- 一次遍历原始文本，计算段落字符偏移和前后文，继续使用既有 CFI 生成及原文校验。
- DOM 遍历和定位按约 1–6 ms 空闲时间片让出页面，阅读页显示后约 600 ms 再启动后台准备；每批向 Worker 传输 40 段。
- 完整索引在 Worker 内序列化、写入和恢复，不在主线程传递整本书的索引。按书籍 SHA-256、章节数和索引格式版本区分缓存。
- 用户主动搜索时提前唤醒任务，并等索引完整后返回结果。关闭或更换书籍会取消旧提取任务。
- 清除缓存同时清理索引；事务更新缓存 epoch，阻止清理前启动的任务随后重新保存旧缓存。缓存损坏、版本不符或存储失败时回退为正常建立内存索引。

## 测量

Windows / Edge 无头浏览器，开发预览；各书使用独立、空的浏览器资料。长任务由 `PerformanceObserver` 的 `longtask` 记录，阈值为 50 ms。时间从导入开始到“全文检索就绪”，包括书籍打开、初始等待与索引准备，优化后还等待缓存保存完成。结果是本机样本记录，不作为所有机器或所有 EPUB 的保证。

| 样本 | 原首次准备时间 | 优化后首次准备时间 | 优化后缓存重开 | 索引提取期间 ≥50 ms 长任务 |
| --- | ---: | ---: | ---: | --- |
| IDPF Moby-Dick，144 节 | 1.57 s | 2.71 s | 0.91 s | 本次未观测到；原最长约 170 ms |
| 原创 1,500 段单章 | 5.36 s | 2.92 s | 0.91 s | 本次未观测到；原最长约 4,584 ms |

两本书的缓存重开都确认 `restored=true`，向 Worker 发送新增索引段落的批次数为 0。Moby-Dick 首次准备总时间变长，是初始让路与分批调度的取舍，阅读页面不需要等该准备过程结束。

长章节的整次冷开仍测到提取时间段之外的长任务（该次最长约 623 ms），不能将本次结果表述为“整个开书过程不再卡顿”或“所有任务均低于 50 ms”。EPUB 加载及阅读排版本身仍有独立开销。

## 正确性验证

- 中英文检索及序列化恢复后的排序和原文定位一致。
- 混合标签、空白、隐藏/导航上下文、嵌套列表和重复原文均可预览、跳转。
- 旧数据库升级保留笔记、进度；清理索引不删除个人记录，清理前的在途构建不能写回。
- 损坏快照自动重建；快速更换书籍不混入旧书的结果。

相关测试位于 `tests/unit/search-cache.test.ts` 和 `tests/e2e/search-performance.spec.ts`。
